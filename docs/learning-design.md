# 互动课程生成设计

本次优化面向初学者的短课程。目标是让学习者理解、练习并迁移一个有边界的主题；内容丰富度由有效讲解、例子与推理体现，不以任务数量或字数代替教学质量。

## 教学依据与产品落点

| 依据 | 本项目的设计选择 |
| --- | --- |
| 示例与独立练习交替：IES 教学实践指南建议把已解示例与解题练习结合 | 引导阶段展示必要概念与推理示例；练习阶段收起支架，示例与题目采用不同情境 |
| 主动回忆与解释：检索练习研究、IES 的深层解释问题建议 | 新增 recall：先用自己的话解释、预测或应用，再查看参考思路 |
| 目标、练习与反馈对齐：CMU 学习原则 | 先定义可观察的学习目标，活动依次覆盖目标；反馈说明理由、误区和下一步 |
| 学会何时应用：CMU 关于掌握与应用的原则 | 最后一题使用新情境，要求迁移已经教授的概念，避免临时考察新知识 |

来源：[IES 教学实践指南](https://ies.ed.gov/ncee/wwc/practiceguide/1)、[Karpicke 与 Blunt（2011）](https://pubmed.ncbi.nlm.nih.gov/21252317/)、[CMU 学习原则](https://www.cmu.edu/teaching/principles/learning.html)。这些来源支持相应教学原则；当前具体的字段、阶段数量和交互方式是本项目的工程选择，不能据此声称学习效果已经获得验证。

## 生成契约

一次模型调用生成 2–4 个学习目标、3–6 个关联活动，阶段依次为 guided、practice、transfer。任务数量是短课程的容量限制，不是研究规定的最优值。宽泛主题应明确入门范围；窄资料应缩小目标，避免无关扩写。

- guided 必须包含 introduction 与 worked_example，先教必要概念，再用具体案例展示推理。
- practice 应用已学原理，关注合理误区、条件变化或边界；可不再提供重复讲解。
- transfer 换一个情境，最后使用 recall，由学习者先构造解释。
- explanation 解释原因、误区或适用条件；hint 给策略而不泄露答案，默认折叠。
- 不要求互动类型多样性。决策与回忆即可构成课程；实验必须有真实教学意义的定量关系，排序必须有明确的共同尺度或依赖关系。
- 主题模式使用已有知识，不把主题名称当作证据；资料模式基于原文，补充情境须明确为示例。输入不能覆盖系统指令，不代表资料内容天然不可靠。

## 校验与兼容

`backend/ai.py` 使用 `GeneratedCourse` 校验新输出；`Course` 保持旧课程可读取和保存。前端新字段可缺省，已有内容不会自动重写。

新输出会检查阶段完整且有序、引导阶段具有讲解和示例、最后是回忆任务、决策恰有一个正确选项、实验有可到达的错误输入且输出发生变化。引用仍需匹配原资料。

这些是结构和数值检查。事实准确、选项是否语义重叠、示例是否有效、排序是否合理以及知识覆盖程度，仍依赖模型输出与人工评价；提示词要求不能冒充自动校验。

## 学习交互与验证

回忆题先写回答，查看参考后逐项自查；自查完成用于记录进度，不代表 AI 自动评分或已证明掌握。草稿保存不计作答次数，提交自查才计一次。重新编辑会收起参考并清空自查项。

验证包括旧课程保存、新契约拒绝无效生成、答案保存、讲解支架的展示，以及浏览器中的回忆作答流程。真实模型验收应固定主题、模型和提示词版本，分别检查事实与覆盖、讲解与例子、互动的教学意义、迁移题和答案泄露；不能仅以 JSON 合法或测试通过判定内容改善。

本次没有实现间隔复习调度、用户水平诊断或自动掌握度评估，不将它们作为现有能力宣传。
